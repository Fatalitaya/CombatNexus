# 领域合约

遵循 [仓库约定](../AGENTS.md) 与 [开发流程](DEVELOPMENT.md)。以下约束用于实现、重构与评审；不以此代替具体能力的源码检查和运行证据。

## 所有权与身份

| 领域 | 责任 |
| --- | --- |
| 服务器执行内核 | 准入、请求身份、父子因果、预算、阶段权限、完成 FIFO 与定义代际 |
| 世界运行时 | 世界会话、服务组合、实体生命周期与显式平台绑定 |
| attribute | 属性定义和单位、有效值及同次捕获的来源明细 |
| formula | 确定性纯计算，不读实体、不发布事件、不自行抽随机数 |
| combat.damage | 伤害通道、阶段、暴击和减伤决策、应用计划与伤害证据 |
| combat.healing | 治疗贡献、来源与接收倍率、实际恢复及溢出分类 |
| combat.shield | 独立护盾余额、预留分配、承伤、破裂、恢复与回执 |
| combat.regeneration | 恢复计划、受伤延迟和合格时间；通过 healing 恢复生命 |
| effect | 来源、叠加、寿命、贡献计划、安装账本与撤销协调 |
| combat 组合策略 | 吸血、反伤、保护等跨域联动，通过领域入口执行 |
| presentation | 从权威事实生成有界说明与展示，不重新执行战斗规则 |
| target 平台实现 | 原生注册、事实采集、真实写入、事件/Mixin、保存及传输 |

表中业务归属不要求实现全部位于 common；代码位置遵循实际依赖。共享内核只管理执行机制，不吞并领域规则。同一收益有唯一执行者；观察原版事实不等于接管，接管必须同步抑制对应原生收益。

注册定义、服务器代际、世界实体会话和单次请求是不同生命周期。线程、UUID、维度 ID、generation、操作 ID、来源描述均不授予写权限。世界替换后旧服务、票据与句柄失效；同 UUID 的新实体不能接收绑定旧实例的写入。查询只查已有会话，不创建、推进 tick、补偿或复活服务。

生命周期入口显式创建、推进和关闭服务。服务器预算时钟与世界游戏时钟分开；同 tick 推进幂等，倒退拒绝。世界卸载撤销贡献并关闭服务，停服关闭世界后再关闭服务器内核。死亡、换维度、重生和退出按各状态的清理/持久化政策处理，不以统一 reset 掩盖所有权。

外部 TIME 驱动的增量以 sequence、request 和原始 ticks 固定身份；预算不足仅续行原请求。显式取消必须匹配这三个值及当前驱动，保留已消费量、未消费余额和已发生效果，取消不表示完成。取消后的原请求重试返回取消回执，不推进时间；完成或取消后允许幂等释放。卸载/停服保存原进度及终态，恢复不重建旧句柄；未取消的剩余增量等待新授权后继续。

## 捕获、定义与数据边界

每个请求固定一个完整定义句柄，在扩展计算回调前捕获参与者、装备、属性、生命、Effect 和来源事实。值与来源一次捕获、一次发布；捕获失败保留旧快照，不消耗修订号。同 tick 后续请求仍重新采样，不能凭相同 UUID、装备引用或 tick 假定输入未变。

输入身份包含世界会话、实体实例、revision、gameTick 和 generation。面板可独立捕获当前状态，但一份面板内必须使用同一捕获边界；历史解释使用历史事实，不能读取 latest 补齐。未知来源、施加者和外部事实明确缺失，不用目标反推主人。原生属性约束和有效值策略由平台观察保留，展示单位显式声明，未知属性不猜单位或是否已被消费。

settings、通道、规则、词条/词缀模板、行为、Effect、治疗、恢复和护盾共同组成候选代际。先解码、校验引用、编译执行与展示数据，再在服务器成功采用资源后整批发布。任何失败保留旧代际，首次失败不借其他服务器的值；旧候选不能覆盖新代际。登录仅同步已采用状态。在途请求保持原句柄，子请求重新捕获当时已采用代际。

数据包同路径定义遵循资源覆盖，原版标签遵循原版合并。严格拒绝未知字段、重复 JSON key、多余尾部、非法范围、非有限定义数值、缺失引用和超预算结构；未实现能力不能加载成功后静默无效。原生原始观察值与合法计算输入分开，不能因加强定义校验改变原生数值约束语义。

预算在解析、捕获、遍历和编码过程中消耗，覆盖深度、节点、条目、Unicode 字符及字节。不能构建完整巨大对象图后才检查，也不能截断权威规则后继续计算。扩展 codec 与物品存储入口同样需要明确预算和信任边界，组件字段不能充当客户端权限证明。

## 执行阶段与失败

身份与权限校验、准入、冻结输入、领域计算、应用前计划、资源写入、终结及通知保持明确边界。计算工作区、不可变应用计划、写入 journal 和业务结算是不同对象；Incoming 数值交接不是生命已提交。

- 请求身份单次消费，拒绝后不能重复提交同一请求。完成通知容量在资源写入前预留；原生入口与其 continuation 复用准入，不重复扣费。
- COMPUTE 存在于执行栈时，拒绝新战斗请求及受管世界写入。处理器只能改授权工作区，不能自行签发票据、进入 APPLICATION、伪造回执或排入完成队列。生命周期权限不可用作业务写入旁路。
- APPLICATION 可同步执行有权限的子请求，子请求独立准入并完成自身应用后返回。它继承真实栈顶父链、权限交集与触发抑制，受根链、深度、tick 和通知容量共同限制；不能借祖先权限或跨服务器身份。
- 计算处理器失败只恢复其工作区与追加计划，不声称回滚外部世界。类型化应用前步骤明确普通拒绝后继续还是终止父操作；部分、未知写入及异常停止剩余步骤，已完成子操作不回滚、不重放。
- 原生事件后的最终观察另入应用证据，不修改冻结的计算输入。绑定实体在写入前重新校验，计算后被同 UUID 新实例替换时拒绝。
- 原生写入后抛错保留确认变化；证据不足为 UNKNOWN，不推断零写入或自动重试。同目标物理写入内重入导致无法区分净差时，不据此发放精确吸血或溢出收益。
- 终态只冻结一次，退出可变作用域后按服务器 FIFO 通知。子请求通知追加队尾，观察者只读；反应仅在声明权限内提交子操作。观察异常不撤销结果、不重复投递、不补抽随机数。
- 作用域、绑定实体和未使用预留在 finally 中释放。短期父权限、采样器及回调能力在退出后失效；保留 ID 或快照不能恢复权限。

事务是同步游戏操作，不提供跨资源 ACID 回滚或跨进程 exactly-once。未准入、取消、零量、全吸收、部分与未知写入分别报告；不能只看 APPLIED 或句柄存在就判断完整成功。JVM 致命错误不作为普通扩展异常吞掉。

## 伤害、治疗、护盾与恢复

伤害保持基础修改、类型缩放、属性缩放、暴击、条件倍率、全局调整、攻击量冻结、减伤设置、防御计算、最终覆盖的顺序。纯重构不得改变真伤、通道、浮点归约顺序或随机消费位置。受控随机决策保存采样事实，不允许同次调用重掷。

伤害类型/标签、伤害通道、可重叠攻击类别、动作身份及资源种类分别建模。生命、原版吸收、自定义护盾池与盾牌格挡不能混用；实际生命损失不等于命中、整次攻击成功或击杀。无法拆分的第三方伤害保持不透明总量，不虚构附魔或装备分项。

原版护甲、保护附魔、抗性 Effect、固有减伤各自使用同一执行归属决策控制计算与抑制。合作模式保留原生机制，不叠加同机制的模组收益；自定义通道抗性仍独立。原生拥有减伤时，不承诺模组每个分量仍保持完整绕过语义。

治疗保持独立管线，明确 TARGET、HEALER、EFFECT_OWNER；未知 healer 不借用目标。固定增量按稳定顺序汇总后统一限幅，再按阶段应用来源和接收倍率，倍率只消费一次。非正或非有限原生治疗输入拒绝，不复活死亡实体；原生事件完成后采样，再执行一次生命写入。直接 setHealth、初始化、读档和生命校正不冒充治疗。

吸血消费完整主伤害已确认的生命损失与捕获比率，排除护盾、吸收、派生及反伤，通过 healing 提交子请求。父伤害不因子治疗失败撤销。

护盾在最终 Pre 后、原版吸收及生命写入前提交。准入先于分配，APPLICATION 先于提交，回执先于发布；reserve 不改变余额，释放后不可提交，重复提交返回原回执。同 tick 清理不能清掉已消费身份。护盾已扣但后续生命写入失败时保留 shieldLoss，不返还；全护盾吸收可以是有效伤害但生命损失为零。

护盾类型/标签与通道过滤共同满足，排序和按分量分摊稳定。纯池状态负责余额、预留、过期、恢复与保存值；世界/线程/目标、注册表及事务权限仍由服务接线检查，内部状态类不成为公开服务入口。

恢复计划通过 healing 写生命，保留合格 tick 聚合、分数进度、受伤延迟与独立战斗窗口。到期计划先安排下一次机会，再逐项校验身份与条件，回调替换后续来源不得执行旧计划；异常后继续调度。跳时不补算，提交前消费进度，取消或满血不积累爆发。死亡、规则关闭和战斗延迟清零进度。食物值、饱和度及消耗度归原版；保留原版计时的恢复入口不得再设一套计时器。

## Effect、来源与扩展

来源身份区分提供者、实例、可知 owner 和槽位，来源描述与叠加身份分离。两个装备槽或两次施法不能共用安装身份；撤销使用该世界会话的真实安装句柄。属性标识使用完整贡献身份，撤销一个来源不能移除另一个。只读来源视图不发放安装权限。

Effect 决定资格、叠加和贡献计划，贡献端口执行 `prepare → apply → receipt → reconcile`。prepare 不提前改实体；按实际安装/撤销逐项记账，部分安装不激活。失败进入受影响来源的待协调状态，补偿只针对确定可补偿的操作；保留已消费保护和触发额度，不能因重装返还。来源提供者失败保留既有来源，不能视为主动撤销全部 offer。

来源撤销取消周期/恢复任务并撤销属性，已授护盾遵循明确的撤销或保留至过期政策。不可变行为组件只存参数，运行状态归安装实例及执行器；新增周期行为复用调度、保存和取消机制，不增加全局计时器或玩法特判。

启动注册按收集、校验、冻结执行，拒绝重复身份、错误实现类型及冻结后注册。排序按所属阶段和已定义稳定键执行，不能依赖偶然加载顺序。扩展只用公开 API，内部 Runtime、票据、生命周期及 SPI 不属于普通扩展入口。同能力/位置有多个替换执行者时拒绝启动；能力声明不等于真实调用已接管。

触发范围明确为操作、目标、动作、根链、来源或时间窗口；ACTION 必须有真实动作身份，不能用同 tick 推断。计数在规定的动作尝试点消费，失败不擅自返还。保护在最终写入前选定并消费一次，未选来源不消费，后续异常不返还成本。

延迟任务只保存有界身份及值，不保留活实体、旧定义仓库或 CombatParent；到期重新解析会话并准入。定义变化时使用安装值还是当前定义须明确。显式持久化来源恢复后获得新句柄；剩余时长、周期剩余延迟、已消费保护、护盾损伤年龄及恢复进度必须保留，装备对账不重复安装或补发。加载失败保留原始数据并停止覆盖保存；generation 不是存储格式版本，不隐式提供旧格式迁移。

## 定义格式

定义位于 `data/<namespace>/<目录>/<path>.json`，ID 为 `<namespace>:<path>`。加载定义不自动安装来源或授予收益。内置资源在 `common/src/main/resources/data/combatnexus`。

| 目录 | 含义 | 每次重载上限 |
| --- | --- | --- |
| combatnexus_behaviors | priority、duration_ticks、components | 256 |
| combatnexus_effects | 生命周期、属性与行为引用 | 256 |
| combatnexus_healing_rules | 治疗条件及贡献 | 64 |
| combatnexus_regeneration | 恢复计划 | 256 |
| combatnexus_shields | 护盾容量、过滤与恢复 | 256 |

伤害定义使用 `combatnexus_channels`、`combatnexus_rules`、`combatnexus_entry_templates`、`combatnexus_affix_templates`。定义 ID 字符串上限 256，ID 列表上限 32 且拒绝重复。

行为组件的 `type` 与参数同层，由注册 codec 解码；`reflection` / `overflow_shield` 的触发限制使用嵌套 `limit`。单行为最多 64 个组件且 type 唯一，priority 为 -10000..10000，duration_ticks 为 1..1200000。周期组件使用 interval_ticks 和可选 first_delay_ticks。内置伤害组件的 damage_type 在本次胜出资源集合检查引用，允许同包新增类型；执行时仍需当前注册表解析。

Effect 的 behaviors 数组及每个行为的 components 保持执行顺序，行为自身 priority 不重排展开结果，计划采用 Effect priority。空引用数组合法；重复引用、跨行为重复 type 或展开超过 64 项拒绝。标签和过滤器是集合，不带执行顺序。

Effect level 为 0..255。lifetime 为嵌套对象：TIMED 需要正 ticks；PERMANENT / INSTANT 仅有 kind。永久不等于不可驱散或自动持久化；瞬时效果不能携带属性/限制，只能用瞬时组件，其他寿命不能包含瞬时组件。治疗与伤害按展开顺序执行，不能交换。

属性最多 32 项，attribute 必须已注册，attribute/modifier 组合唯一；stacking 必须已注册。tags 缺省空集合，display 缺省空，可显式包含 native_id、ambient、particles、icon、aggregate_sources、persistent、environment。装备来源使用类型化多绑定组件，不恢复旧 custom_data 字符串入口。

治疗规则 phase 仅为 CONTRIBUTIONS / LIMITS，不能替代 RECEIVED；空选择器表示不限制，生命比例在 0..1 闭区间。恢复定义明确速率、受伤延迟、游戏规则、脱战条件及期限。护盾定义明确容量、优先级、类型/标签/通道、恢复及叠加，通道引用验证本次候选注册表。

## 展示、缓存与诊断

活动 Effect 与面板来自服务端权威快照；客户端格式化和排版不成为第二套权威计算。物品说明直接读取当前 ItemStack 的已保存组件并复用描述器，ID 引用使用同步定义；不查服务端槽位、不等待实例回包，不用静态模板替代实例数值。缺失、空投影或渲染失败保留原版及其他模组提示，不追加失败说明；先在副本完成渲染再更新列表。

共同描述保存标题、作者摘要、生成说明、详情、条件树及有序操作，不传输可执行对象或 registry holder。作者摘要优先，Shift 展开详情，调试独立；数值与单位明确，比例增量用百分点、倍率用百分数、时长按 tick 传输。摘要绑定只访问描述器声明的 slot，不执行表达式，缺失或歧义拒绝投影。隐藏组件与高级提示门禁不得因新说明泄露。

缓存按实际协议关联会话、实体、代际及修订，旧消息不能自行采用新代际；断线、玩家/维度变化和重载使对应旧状态失效。服务端先核对请求身份，再查询世界服务。预算前置，超限返回明确拒绝，不展示旧实例冒充新结果。

热路径不解析 JSON、拼提示文字或复制整份历史。诊断保存冻结事实的有界投影；历史淘汰或截断明确标识，不能事后读实体补齐。日志关闭、投影失败和缓存拥塞不得改变数值、随机、阶段、触发次数或完成发布。异步仅处理冻结 DTO，不传活实体、可变 ItemStack、Runtime、授权或持有它们的闭包。优化先测量，不先引入对象池、全局数组或堆外状态。
